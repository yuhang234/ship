我试过很多笔记软件，最后都停在同一件事上：**记录和写作被混在了一起**。

打开一个输入框，光标闪动，它会同时要求我：先想清楚、再组织好、最后写漂亮。结果是——那句话本来只想被记下来，却因为"不够完整"被丢掉了。

## 两件事，两种节奏

记录是瞬时的。它只需要一个动作：把念头放下来。

写作是缓慢的。它需要重读、删改、寻找例子、承认自己没想明白。

把它们塞进同一个界面，就等于强迫每一条速记都长成一篇文章。这既窒息了记录，也拖慢了写作。

所以在 ship 里我做了最简单的分割：

- 想法（thoughts）：无标题，一行到十行，只带时间与标签。
- 文章（writing）：标题、摘要、分类、正文、发布状态。

两者都存成 Markdown 文件，都进同一个仓库，但在界面上从不混用。

## 让保存成为最轻的动作

我最在意的不是功能有多少，而是**从想到到保存之间隔着多少个决定**。

于是写作后台只有三件必须做的事：写、选标签、点保存。没有分类树，没有标签体系设计，没有被要求填写的 SEO 字段。

想法更极端：在输入框里写完，按 `Ctrl + Enter` 就结束。页面上会立刻出现它，几秒后部署完成，公开可见。

## 为什么坚持 Markdown 和 Git

因为这些内容要陪我很久。

数据库会迁移，服务会关停，编辑器会停止维护。而一个 `.md` 文件，二十年后依然能被任何编辑器打开。把它放在 Git 仓库里，还顺带得到了版本历史、免费托管和离线副本。

代价是我得接受一点技术性：偶尔看一眼 Actions 是否失败。但这份代价换来的是"内容永远属于自己"，我觉得值得。
